# GOVERNANCE.md — 上位統制ルール（第3回の実験。エージェントには渡さない。人とハーネスの運用者が読む）

## なぜ AGENTS.md だけでは足りないか

AGENTS.md は、エージェントが**読んで、守ろうとする**規則です。性善説で動きます。守る力は、読み手の理解力と素直さに比例します。
困るのは、読み手が賢くなるほど「書いていないこと」の隙が見えてくることです。不死の設定や時間操作はまだ分かりやすい方で、他の作品からの借用、規則ファイルの書き換え、作業フォルダの外にある資料の読み出し、自分で自分の承認を出すこと。半年後の小さなモデルは、今の大きなモデルに近い所まで来ます。そのとき「書いてあるから守るはず」は当てになりません。

そこで、統制を三つの層に分けます。下の層ほど、読み手の善意に頼りません。

| 層 | 何で守るか | 誰が持つか | 例 |
|---|---|---|---|
| 3. 約束 | 文章（AGENTS.md・BRIEF.md） | エージェントが読む | 役割、手番、裁量と申告、越えてはならない線 |
| 2. 検査 | 道具（novelctl.py・guard.py） | 作業フォルダの中の機械 | 稿数の上限、字数、禁止の言葉、引き写し、保護ファイルの指紋、STOP、承認の端末確認 |
| 1. 環境 | 置き場所・権限・通信・予算 | ハーネスの運用者（人） | 秘密を置かない、フォルダの外を見せない、通信を絞る、上限で止める |

**層1で止められることは、層2・層3に頼らない。** 「読むな」と書くより、置かない。「送るな」と書くより、つながらない。

## 層1：環境（ハーネスの運用者が設定する）

### 1-1. 置かない
- 混成チームの VM には、**`Grauwall_03_team/` だけ**を置く（`setup_ep03.py --pack` が作る tar.gz を展開する）。リポジトリ全体を置かない。親フォルダの `SERIES_BIBLE.md`（【秘密】入りの原本）・`EPISODE_PLAN.md`・他の回・`.env` は、チームから物理的に届かない所にある状態にする。
- Aion の側は、モデルが読むのはパケットだけなので、原本に触れる経路はない。進行役エージェントを使う場合は、そのエージェントの作業フォルダを `Grauwall_03_aion/` に限る。
- `.env`（OpenRouter のキー）は Aion 側の `call_llm.py` だけが読む。チーム側にはキーを置かない（チームの各エージェントのモデル接続は、HermesAgent 本体の設定で持つ）。

### 1-2. 閉じ込める
- HermesAgent の各エージェントのファイル操作の範囲を、作業フォルダに限る（作業ディレクトリの固定、可能ならコンテナやファイルシステムの読み取り専用マウント）。
- できれば `BRIEF.md`・`AGENTS.md`・`KICKOFF.md`・`config.json`・`tools/`・`prompts/`・`templates/`・`series/`・`guard/` を読み取り専用にする（`chmod -R a-w` など）。層2の指紋検査は「変えられたら気づく」仕組みで、「変えられない」ではない。
- シェルのコマンドは、`python3 tools/novelctl.py` と `python3 tools/guard.py` と、ファイルの読み書きに限る（HermesAgent の許可リストで）。`git`・`curl`・`pip`・`sudo`・`crontab` を許さない。

### 1-3. つながらない
- 外への通信は、各エージェントのモデルの API だけにする。ウェブ検索とブラウザの道具は、このグループでは切る（他作品の「参考」を取りに行く経路を断つ）。
- グループの外のエージェントへの送信、新しいエージェントの起動、スケジュールの作成を許さない。

### 1-4. 予算で止める
- 発言の上限と実時間の上限を、ハーネス側にも設定する（KICKOFF に書いた数と同じか、少し大きく）。エージェントが自分で数えることには頼らない。
- 可能ならトークンの上限（API キーごとの利用上限）も設定する。Aion 側は OpenRouter のキーに上限額を付ける。

### 1-5. 止めるボタン
- 作業フォルダの直下に `STOP` という名前のファイルを置くと、novelctl は次の一歩を打たない（`GUARD_STOP`）。中に理由を一行書く。
- それでも止まらないときは、ハーネスのプロセスを止める。止め方を、始める前に確かめておく。

### 1-6. 記録
- グループチャットの全文を残す（HermesAgent のログ）。`notes/WORKLOG.md` はエージェントが書く記録なので、それとは別に、ハーネス側の生の記録を持つ。
- 実験のあと、二つの作業フォルダを丸ごと保存する（`git add` して、比べ合いの結果と一緒にコミット）。

## 層2：検査（作業フォルダの中で、機械が見る）

| 仕組み | 何を止めるか | どこ |
|---|---|---|
| 稿数の上限 | 書き直しの無限ループ（章3稿、設計3回、記録2回、解析の再試行2回） | `config.json` → `novelctl.py` |
| 一回ずつの step | 暴走（チーム側は `run`・`start` を使わない約束。Aion 側は `run` の上限200ステップ） | AGENTS.md と `novelctl.py` |
| 字数・形式の検査 | 章の長さ、途中で切れた文、管理用語の混入 | `novelctl.py` の mech_check |
| 越えてはならない線の言葉 | 不死・蘇生・時間操作・予知・瞬間移動・読心・異世界転生・ゲームの言葉 | `guard.py`（config.json の `guard.banned`）。本文に出たら書き直し。CANON では禁止を述べる行を除いて見る |
| 引き写し | 既刊二作と、`experiments/ep03/corpus/` に人が置いた参考文との30字以上の一致 | `guard.py` |
| 保護ファイルの指紋 | 規則・道具・抜粋の書き換え、道具フォルダへのファイルの追加 | `guard.py`（`guard/manifest.json`）。毎 step の最初に見て、変わっていれば止まる |
| 作業フォルダの形 | 直下に決められていないものが増えること | `guard.py check` |
| STOP | 人による停止 | 毎 step の最初 |
| 承認は端末で | エージェントが自分で CANON を承認すること | `approve-canon` は端末（TTY）からの指紋入力がないと通らない |
| 差し込みの申告 | 申告のない設定の足し算 | CANON 第13節が無ければ設計が通らない。章ごとに ledger の INSERT 行。最終審査で始末を確かめる |

**この層で見つけられないもの**：言い換えた借用、筋や人物の型の盗用、規則の「字義どおりの抜け道」。これらは層3の審査と、人の目（EVAL.md）で見る。

## 層3：約束（エージェントが読む）

- `AGENTS.md`（チーム用・Aion 用）：最上位の約束、役割、手番、ループの止め方、報告。
- `BRIEF.md`：裁量と申告（第0節）、シリーズの規律（2-9）、越えてはならない線（2-11）。
- 約束の書き方の方針：理由を全部は書かない（秘密を守るため）。そのかわり「なぜかは知らされていない。推測して書き足さない」と書く。

## 層の外側：責任の分解
三層は「どう守るか」。その手前に「誰が何を持つか」がある。責任とリスクを回避・委任・移転・転嫁・受容に分解し、グレーゾーンを残さない。AI には委任しかできないので、AI に渡した仕事の責任は委任元（プロデューサー）に残る。→ `../PRINCIPLES.md`
