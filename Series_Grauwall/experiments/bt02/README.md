# bt02 — 複数の下読みを束ねて、分岐する未来のプロットを書かせる（第2段）

bt01（第1段）で分かったこと：分岐点を一つずつ見つける（検出）はどのモデルもかなりできるが、組み合わせて一本の別の世界線にする（相関）は、どのモデルもできなかった。

第2段は分業にする。

1. **集約**（機械）：6本の下読みの答えを、原文の位置で束ねて「決定論的でない事象の一覧」（`work/SIGNALS.md`）にする。正解表は使わない。モデル名は伏せて A〜F にする。何本が挙げたか（検出の多数決）を付ける。
2. **相関**（モデル）：原文と事象の一覧を渡し、事象を組み合わせて、原文と矛盾しない別の世界線を3〜5本作らせる。

## 仮説（プロデューサー）

- 原文全体と事象の一覧を同時に抱えて組み合わせるのは、コンテキストが大きくアテンションが幅広いフロンティアモデルの仕事。効率重視のモデルにはかなり厳しい。
- 小説の手がかりは、読み手の注意を惹かないよう**ひっそり**置かれる（一度だけ出る物、冗談の中の一言）。プログラムでは大事なものほど何度も参照されて目立つので、注意の向け方が逆。ツール操作やコード生成に寄せて学習されたモデル・ハーネスは、この読み方に合わないのではないか。

依頼文にはこの仮説に沿って、「挙げた数が少ない事象を軽く見ない」「離れた二つの箇所を突き合わせると見分けられる手がかりを優先する」の二点を入れてある（ハーネスの設計の一部）。これを外した版との比較は、次の試験でできる。
